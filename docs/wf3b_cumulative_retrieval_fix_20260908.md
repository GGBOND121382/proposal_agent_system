# WF-3B 补查证据累计合并

补查结果现在先与首轮证据合并，再做采纳判断。第二轮某条原查询没有命中时，首轮对应证据仍可保留，第二轮新增的有效来源也能进入综合与导出。

## 实现

- `app/skills/research_merge.py`：校验两轮归档、项目/工作流归属与增量计划约束；按规范化 URL、DOI、相同文本快照去重，并创建独立的累计归档。
- 同一来源优先选择可验证的全文。跨快照转移查询关联前，检查所选快照是否实际支持该查询；若新版内容已经变化，不再支持首轮已覆盖查询，则保留支持该查询的旧版本。
- 首轮来源 ID 保持稳定；所有原始来源 ID、归档会话、快照路径、哈希与查询关联保存在 `merge_provenance`。`selected_snapshot_origin` 标明实际采用的版本。
- 重新生成来源目录、引用片段、覆盖率、全文统计、充分性、缺口和验证包。原始归档不改写，合并过程不发起网络请求。
- `BackgroundResearchService.merge_search_results()` 接入 WF-3B 搜索结果采纳分支。后续综合、审查和导出读取累计结果。无磁盘归档的旧模拟数据继续使用原模拟路径。
- 保留查询集合、查询覆盖与归档完整性保护。维度退化检查按首轮查询范围进行；新增查询自己的未解决缺口不会被误判成首轮覆盖退化。最终充分性仍按完整新计划计算。
- 检索健康描述最新实际检索轮次，两轮原始健康信息留存在合并报告。搜索命中数可跨轮累计，但明确标记包含重复命中；来源数、可用证据数、全文数均按合并去重后计算。
